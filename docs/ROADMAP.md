[ARCHITECTURE.md](./ARCHITECTURE.md).

## ⚠️ Текущий приоритет — рабочий MVP без AI

**Решение (2026-06):** сначала выпустить *реально работающий* MVP роутинга без
всяких AI-поверхностей. Порядок ниже **сознательный** — карта + роутинг + POI
идут первыми; эмбеддинги, MCP-сервер, чат-компаньон, геймификация явно
**отложены** (🕒).

1. **POI-слой (только гео)** — сущность + ингест (без эмбеддингов). ✅
2. **Прокси роутинга** — реальные маршруты GraphHopper, точка-в-точку + round-trip. ✅
3. **MapLibre-карта MVP** — MapLibre GL JS + Protomaps PMTiles, изохрона, мульти-POI, GPX ✅
4. **Обогащение данных** — тексты Wikivoyage + фото Commons на POI (питает карточки). 🚧
5. **Telegram-поверхность** (Фаза 6.5) — второй интерфейс: локация → карточки → маршрут → GPX. 🚧 (база готова)
6. *Затем* вернуться к «интересности»/погоде (Фаза 6), эмбеддингам/семантике/MCP/компаньону, геймификации — 🕒.

### Бета 0.1 — внутреннее закрытие релиза 🚧

База имеет датированное operator-recorded наблюдение production (2026-08-1x):
audit `pfo-v0.1-v1` с 30 359 POI и PFO GraphHopper с семью профилями (`car`,
`bike`, `bike_touring`, `mtb`, `mtb_leisure`, `foot`, `foot_scenic`). Это
технический снимок состояния; перед следующим импортом повторяются dry-run,
backup, import/audit и health-проверки, а каждый code change и итоговый аудит
одобряет отдельный reviewer.

Не являются закрытой приёмкой: снимки web desktop/mobile, Mini App acceptance и
Telegram device acceptance. Карта в бете не полностью self-hosted; replacement
bot token/device и чистый публичный GitHub baseline после ротации секретов —
внешние owner gates. См. [чек-лист беты](./beta-acceptance-checklist.md).

## Фаза 0 — Вычистить шаблон ✅

Удалены модули бэкенда (`events`, `reminders`, `settings`), вьюхи фронтенда, API-клиенты,

**Приёмка:** `build:backend` + `build:frontend` зелёные. ✅

## Фаза 1 — Инфраструктура дата-сервисов ✅
**Цель:** поднять Postgres (geo+vector) и GraphHopper (роутинг+высоты) через Docker.

- `docker/docker-compose.yml`: `db` (postgis+pgvector) + `graphhopper`.
- `docker/postgres/` (Dockerfile pgvector + `init-extensions.sql`: `postgis`, `vector`, `pg_trgm`).
- `docker/graphhopper/config.yml`: семь профилей (`car`, `bike`, `bike_touring`, `mtb`, `mtb_leisure`, `foot`, `foot_scenic`), высоты SRTM; CH только для `car`, LM для гибких профилей.
- `scripts/download-osm.sh`: загрузчик Geofabrik PBF для выбранной территории.
- Бэкенд: только PostGIS-конфиг TypeORM.

**Приёмка:** сборки зелёные; compose-файлы валидны; запушено в `main`. ✅

## Фаза 2 — POI-слой + ингест ✅ (гео; эмбеддинги отложены)
**Цель:** запрашиваемые POI (гео + двуязычность) в PostGIS из OSM.

**Бэкенд (готово):** модуль `pois` (`PoiEntity`, двуязычные имена/описания,
popular/featured, **без** колонки эмбеддингов пока), `PoisService` с PostGIS-запросами
bbox/radius/category через колонку `geom` + GIST-индекс. Эндпоинты: `GET /api/pois`,
`/api/pois/:id`, `/api/pois/count`. Админский CRUD (`/api/pois/:id` PATCH) с переопределениями.
**Фронтенд (готово):** клиент `api/pois.ts`; POI как маркеры по категориям + карточки.
🕒 Wikivoyage/Wikidata-обогащение — см. Фазу 2.5. 🕒 Эмбеддинги отложены (открытый вопрос #3).
**Приёмка (MVP):** ✅ сборки; 30 000+ POI ПФО загружены в прод-БД.

## Фаза 3 — Прокси роутинга (GraphHopper) ✅
**Цель:** обернуть GraphHopper за бэкендом; сценарии A и C работают end-to-end.

**Бэкенд (готово):** модуль `routing` (capability): `GraphHopperClient` (HTTP,
`points_encoded=false` → готовый GeoJSON, высоты, `ch.disable`) + `RoutingService`.
Эндпоинты: `POST /api/routing/route`, `POST /api/routing/round-trip`, `GET /api/routing/health`.
Также `POST /api/routing/plan` (объединённый A/B) + решатель TSP (`routing/tsp.ts`).
🕒 Отложено: реверс-геокодинг (открытый вопрос #1), кэш маршрутов.
**Приёмка:** ✅ сборки; реальные маршруты с высотами работают. Для беты health должен подтвердить все семь production-профилей.
**Зависимости:** Фаза 1 (GraphHopper).

## Фаза 4 — Карта MapLibre + UI ✅ (иммерсивный MVP готов; полировка позже)
**Цель:** настоящая, выразительная интерактивная карта — главный экран Nearventure.

**Готово (MVP):**
- **Дизайн-система:** шрифт Geologica + Material Symbols + тёплая палитра Material 3
  (light + dark) как CSS-переменные. Подпись: полноэкранная карта со «стеклянным»
  «Adventure Control Center» и нижним drawer-ом карточек.
- **`AdventureView.vue`** (главная `/`): полноэкранный MapLibre GL JS на ПФО, Protomaps PMTiles
  (`/tiles/pfo.pmtiles`), переключатель слоёв (CyclOSM / Схема / Спутник).
- **Мульти-POI роутинг (сценарий B):** тап по маркерам добавляет остановки — маршрут
  перестраивается через все выбранные, пронумерованные в порядке посещения.
  Тумблеры «Кольцо» (возврат) и «Короткий порядок» (TSP через бэкенд `optimizeOrder`).
- **Сценарий C (бюджет времени):** слайдер времени → изохрона досягаемости + POI с
  «стоимостью» в минутах (метафора корзины). Два режима:
  - **Авто-подбор:** выбери категории — система сама генерует петлю с обогащением POI.
  - **Ручной:** кликай по конкретным POI → маршрут по точкам (TSP).
- **`enrichWithPois`:** при построении маршрута система предлагает POI рядом с путём,
  оценивает отклонения и показывает, что можно посетить «по дороге».
- Карточки POI (фото + двуязычное имя + категория), детальная карточка, перетаскиваемый
  старт, геолокация, сводка дистанция/время/набор высоты, **GPX-экспорт в один клик**.

🕒 Отложено: кластеризация POI; график высот; i18n; истинный скоринг живописности (Фаза 6).
  shadcn-vue и сохранённые маршруты уже реализованы.
**Приёмка (MVP):** ✅ сборки; мульти-POI роутинг + варианты + GPX работают.
**Зависимости:** Фаза 2, Фаза 3.

## Фаза 5 — MCP-сервер + чат-компаньон ⬜
**Цель:** две новые поверхности над теми же capabilities.

- **MCP (бэкенд):** `@modelcontextprotocol/sdk`, Streamable HTTP, в процессе NestJS.
  Read-mostly capabilities как MCP-инструменты. Auth по API-ключу.
- **Чат-компаньон (фронтенд):** Vercel AI SDK core (`streamText`/`tool`/`stopWhen`) в
  браузере, BYO-key. UI-tool registry пишет в те же `MapStore`-refs, что и клики.
- 🕒 **VRM-аватар компаньона** (экс-Фаза 6.7, после насыщения описаний POI):
  живой проводник-кошко-девочка в WebXR (three.js / @pixiv/three-vrm) поверх
  того же чат-компаньона — lip-sync на речь, взгляд на обсуждаемый POI,
  эмоции на открытие редкого объекта, голосовой диалог (TTS/STT ru).

**Приёмка:** внешний агент подключается по MCP, строит маршрут; in-app компаньон по
ключу находит POI и рисует маршрут через tool-calls.
**Зависимости:** Фазы 2-4 (VRM-аватар — также Фаза 6.6 для базы описаний).

## Фаза 6 — «Магический» round-trip (сценарий C) ⬜
**Цель:** генерировать *действительно интересные* петли на «у меня есть N часов».

- Уровень 1: GraphHopper `round_trip`, несколько вариантов со скорингом интересности.
- Уровень 2+: гибридная изохрона + кластер POI + бюджетно-ограниченный выбор TSP.
- Скоринг интересности (категория, рейтинг, разнообразие, набор высоты для тренировок).
- 🕒 **Погодная осуществимость:** штрафовать грунтовые/лесные сегменты после дождя.

**Приёмка:** «4 часа, велосипед, у воды» → разумная петля вдоль POI (без грязи).
**Зависимости:** Фазы 3-4. Это R&D/дифференцирующая фаза.

## Фаза 6.5 — Telegram-поверхность 🚧 (база готова)
**Цель:** бот как самостоятельный продукт «что рядом + поехали» сразу после
обогащения POI данными Wikivoyage/Commons. Переиспользует те же capabilities —
нулевой дубликат логики.

**Почему рано:** это первая zero-install мобильная точка входа и вторая поверхность,
доказывающая архитектуру «N транспортов над одним capabilities-слоем» (ADR-006).

**Scope (база, эта фаза) — готово:**
- **grammY** как NestJS-провайдер (без `@grammyjs/nestjs` — ADR-009). Тот же процесс, ≈0 RAM.
- Получение геолокации → `pois.find` (радиус) → **карусель карточек POI**.
- Выбор POI → ответ **location-сообщением** (открывается в нативных картах).
- `/route` / `/loop` → `routing.pointToPoint` / `routing.roundTrip` → сводка + **GPX-файл**.
- TG-native UI: inline-кнопки, markdown.
- **Mini App** на `/tg/`: каталог и предпросмотр маршрутов (Vue + Telegram WebApp SDK).

🕒 Отложено в Фазу 7 (геймификация): миссии `/quest`, захват медиа → объектное хранилище, XP/бейджи.
**Приёмка:** кинуть локацию → карточки POI → тап → geolocation-ответ; `/loop 2h bike` → маршрут + GPX.
**Зависимости:** Фаза 2 + шаг обогащения (Wikivoyage/Commons). НЕ от Фазы 6.

## 🚧 Фаза 6.6 — Насыщение описаний локальным Deep Research
**Цель:** сделать базу POI достаточно «жирной» для AI-помощника — с качественными
двуязычными описаниями, историей, контекстом по каждому объекту, а не только
короткими тегами OSM.

- Локальный Deep Research-пайплайн (RAG по региону: краеведческие тексты, Wikipedia,
  архивы, ЕГРКН-паспорта ОКН) → обогащённые `desc_ru`/`desc_en` с провенансом.
- Контроль галлюцинаций: каждое утверждение привязано к источнику; факты без источника
  не попадают в карточку.
- Перерасчёт эмбеддингов (pgvector) после насыщения — открывает семантический поиск.
- Человек-в-цикле: черновик от модели → ревью куратором → публикация.

**Приёмка:** выборка из N POI имеет развёрнутые описания с цитированием источников;
семантический поиск «озеро для купания» находит релевантное.
**Зависимости:** Фаза 2 + решение по провайдеру эмбеддингов (открытый вопрос #3).

## Фаза 7 — Миссии и геймификация (сценарий D) ⬜
**Цель:** превратить Nearventure в геймифицированную воронку сбора данных поверх
уже выпущенных поверхностей.

> **Telegram-бот перенесён раньше** — см. Фазу 6.5. Его *база* (обнаружение + роутинг +
> GPX) выходит после обогащения данных; только *геймифицированный* слой остаётся здесь.

**Миссии и геймификация (бэкенд):**
- Сущности `missions` + `mission_attempt` + `player`. Типы: photo-360/video-orbit,
  audio-ambient, documentation, verification, mapping.
- Capabilities: `missions.findNearby`, `missions.generate`, `missions.capture`.
- Геймификация: XP / бейджи / серии на `clientId` (без логина). Анти-абуз.
- Подключение `/quest` + захвата медиа в уже работающего бота (Фаза 6.5).

**Обучающие материалы по контрибьюту в открытые сервисы:**
- Короткие встроенные гайды: «как добавить точку в OSM», «загрузить фото на Wikimedia
  Commons», «проверить объект в полевых условиях», «правильно сделать облёт для
  Gaussian Splatting».
- Шаги миссии = чек-лист с подсказками прямо в боте/на сайте.
- Снижение порога: анонимные OSM Notes (без аккаунта), проверенные allowed.

**Сбор данных для Gaussian Splatting и звукового архива:**
- Миссия `photo-360`/`video-orbit`: 4K@60 облёт объекта → офлайн-пайплайн гауссовского
  сплаттинга (на отдельной GPU-машине; Nearventure — только воронка сбора, ADR-008).
- Миссия `audio-ambient`: запись того, как звучит место → звуковой архив / ambience-датасет.
- Медиа → внешнее объектное хранилище (S3/R2/B2); VPS хранит только метаданные + ссылки (ADR-007).
- Связка с проектом MetaVyatka (цифровая память региона: 3D/звук/фото-архив).

**Контрибьюты наружу:** OSM Notes (анонимно — проверено, разрешено). Wikimedia Commons
(открытый вопрос #6: локально / общий бот-аккаунт / OAuth пользователя).

**Приёмка:** `/quest 2h 10km` → маршрут с остановками-миссиями; выполнение миссии даёт
XP и сохраняет медиа вне VPS; наблюдение уходит как OSM Note.
**Решения нужны заранее** (ARCHITECTURE §15 #5-7): провайдер медиа, модель Commons, дизайн геймификации.
**Зависимости:** Фаза 6 + Фаза 6.5 + решение по объектному хранилищу.

## PMTiles — собственные векторные тайлы ✅ (ADR-005)
Карта уже работает на PMTiles (`pfo.pmtiles`, 957 МБ) через Protomaps + MapLibre GL JS.
Тайлы отдаются nginx-статикой. Растровые оверлеи (CyclOSM, Waymarked Trails) —
поверх вектора, не вместо.

- ~1 ГБ на диск вместо 10–20 ГБ растра;
- одна файла на весь ПФО, без тайл-сервера;
- базовая подложка self-hosted, но внешние glyph/sprite и raster/terrain assets остаются ограничением беты.

## Сквозные задачи (применять внутри фаз)

- **Популярность без аккаунтов:** таблица `interaction` + `clientId` + периодический

- **e2e:** расширять Playwright CDP-каркас на каждую фичу.
- **Деплой:** переиспользовать deploy-скрипты; добавить swap(4 ГБ) + docker compose на VPS.
- 🕒 **Погода:** текущие и за-N-дней осадки из открытого API → хранятся локально,
  питают скоринг интересности Фазы 6 (избегать грязи после дождя).
- **Обогащение данных** (после Фазы 2): листинги/тексты Wikivoyage + фото Wikimedia
  Commons → двуязычные описания + изображения на карточки. Ворота для Фазы 6.5 (боту
  нужны богатые карточки).
