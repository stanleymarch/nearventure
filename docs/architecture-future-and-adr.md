## 8. Чат-компаньон (фронтенд, BYO-key) — ⬜ план

«Магическое окно». Плавающий компаньон, в который пользователь опционально входит.

**Дизайн — инструменты двух семейств, LLM видит один плоский список:**

| Семейство | Что | Куда уходит вызов |
|-----------|-----|-------------------|
| **Data-tools** | Получить данные (найти POI, построить маршрут) | → наш бэкенд REST |
| **UI-tools** | Сдвинуть карту, поставить маркер, нарисовать маршрут, открыть карточку | → **локально в браузере** (Vue/MapLibre) |

Цикл идёт **в браузере** (ключ не покидает localStorage, не касается нашего бэкенда):

```
user: «хочу 3 часа на велике к воде, кольцом»
  ↓
фронтенд строит список инструментов = data-tools (из бэкенда) ∪ ui-tools (локальный реестр)
  ↓
POST api.openai.com  (ключ пользователя, tools=[...])   — Vercel AI SDK streamText
  ↓
LLM: pois_semantic("лесное озеро")   → fetch /api/pois/semantic
LLM: route_roundTrip(start,budget)   → fetch /api/routing/round-trip
LLM: map_drawRoute(geojson)          → routeLayer.value.setData(...)   ← ЛОКАЛЬНО
LLM: map_flyTo(center)               → map.value.flyTo(...)           ← ЛОКАЛЬНО
LLM: «Нашёл петлю 38 км через озеро Шармак, вот она»
```

**Реестр UI-tools пишет в те же реактивные refs, что и ручные клики** → компаньон и
пользователь делят одно состояние. Компаньон — со-пилот, не параллельная вселенная.

**Opt-in:** плавающая кнопка (свёрнута по умолчанию). Первый клик → если нет ключа,
мини-форма («вставьте OpenAI-ключ, хранится только в браузере»).

**Заметка о безопасности (честно):** ключ в localStorage — стандарт для BYO-key, но
утекает при XSS. Митигации: строгий CSP, никаких сторонних скриптов, ключ уходит только
LLM-провайдеру. Это компромисс BYO-key, не скрытый.

## 9. MCP-сервер (бэкенд) — ⬜ план

Чтобы внешние агенты (например, чей-то Claude) пользовались Nearventure «не открывая фронтенд».

- **SDK:** `@modelcontextprotocol/sdk`, работает в **том же процессе NestJS** (без доп. RAM).
- **Транспорт:** Streamable HTTP (стандарт 2025; замена старому dual HTTP+SSE).
- **Инструменты:** тот же слой capabilities (преимущественно чтение: найти POI, построить маршрут).
- **Auth:** API-ключ (bearer, из env). Агент приносит свой LLM; мы его не видим и не оплачиваем.

## 10. Популярность без аккаунтов

Логин не требуется. Стабильный `clientId` (uuid, localStorage) + таблица `interaction` +
периодический пересчёт `popularityScore`. Админ-флаг `featured` + админка = кураторская
рука. UI: сортировка POI по популярности, секция «популярное рядом», кнопка-звезда (лайк без логина).

## 11. i18n (ru/en) — двуязычно с первого дня

- **Данные POI:** `name_ru, name_en, desc_ru, desc_en` (+ fallback `name`). Ингест
  заполняет оба из OSM `name:ru`/`name:en`, лейблов Wikidata, листингов Wikivoyage.
- **UI:** `vue-i18n`, `ru.json`/`en.json`, переключатель, персист + авто-детект браузера.
- **Подписи карты:** язык — параметр темы Protomaps (переключается с локалью).

## 12. Миссии, геймификация и контрибьют — ⬜ план

**Система квестов** превращает Nearventure в геймифицированную воронку сбора данных
(сценарий D). Достигается всеми поверхностями — веб, MCP, компаньон **и Telegram-бот**
(`/quest 2h 10km bike`).

### Типы миссий (привязаны к POI или маршруту)

| Тип | Что делает пользователь | Куда питает |
|-----|-------------------------|-------------|
| `photo-360` / `video-orbit` | Обойти/объехать POI снимая в 4K@60 | Офлайн-пайплайн **gaussian splatting** (отдельная GPU-машина) |
| `audio-ambient` | Записать, как звучит место | Звуковой архив / ambience-датасет |
| `documentation` | Отметить состояние исчезающего/труднодоступного места | Commons / наш архив |
| `verification` | Подтвердить, что POI существует / часы работы корректны | **OSM** (verification notes) |
| `mapping` | Заполнить недостающие атрибуты OSM (покрытие, доступ, …) | **OSM** (Notes — без аккаунта) |

### Цикл наград (геймификация = стимул)

Выполни миссию → **XP / бейджи / серии** → захваченное медиа сохраняется → опционально
контрибьютится назад (OSM Note / Commons). Игровой слой существует *чтобы сбор произошёл*.

### Обучающие материалы

Встроенные мини-гайды прямо в боте/на сайте: «как добавить точку в OSM», «загрузить
фото на Wikimedia Commons», «сделать правильный облёт для Gaussian Splatting», «проверить
объект в полевых условиях». Шаги миссии = чек-лист с подсказками. Снижение порога: анонимные
OSM Notes (без аккаунта, проверено — разрешено).

### Честные развилки (решения до Фазы 7)

| # | Развилка | Реальность | Опции |
|---|----------|-----------|-------|
| 1 | **Хранение медиа** | 4K@60 тяжёлое; **30 ГБ VPS не быть основным хранилищем**. | (a) внешнее объектное хранилище S3/R2/B2; (b) TG-бот как релей (пользователь шлёт → пересылка в хранилище). |
| 2 | **Контрибьют в OSM** | ✅ **Анонимные Notes разрешены** (проверено); прямые правки — нет (только OAuth). | Наблюдения → OSM Notes без аккаунта. Идеально ложится на «без аккаунтов». |
| 3 | **Загрузка в Wikimedia Commons** | Требует **OAuth2** — не анонимно. | (a) хранить локально + ручной экспорт позже; (b) общий бот-аккаунт (оговорки по лицензии/атрибуции); (c) OAuth своего Commons-аккаунта. |
| 4 | **Gaussian splatting** | Тяжёлый GPU-пайплайн, не рантайм. | Nearventure — только **воронка сбора** (метаданные + raw video). Сплаттинг — офлайн на отдельной GPU-машине. |

### Дополнения к модели данных

- **`mission`**: `id, poiId, type, title_ru, title_en, instructions_ru, instructions_en, reward, status, ...`
- **`mission_attempt`**: `id, missionId, clientId, status(pending|completed|rejected), mediaRef, contributedTo, createdAt`
- **`player`** (на `clientId`, без логина): `xp, badges(jsonb), streak, level`

## 13. Инфраструктура и деплой

```
nnginx (reverse proxy + статика тайлов/SPA)
 ├─ backend (NestJS)
 ├─ frontend (собран в backend dist, раздаётся бэкендом или nginx)
 ├─ postgres + PostGIS + pgvector
 ├─ graphhopper  (PBF ПФО + SRTM)
 └─ тайлы: /var/tiles/pfo.pmtiles как статика nginx
```

Бюджет VPS (2 vCPU / 4 ГБ / 30 ГБ + 4 ГБ swap):

| Сервис | RAM | Диск |
|--------|-----|------|
| GraphHopper (bike+foot, `-Xmx1500m`) | ~1.7 ГБ | ~4 ГБ (graph-cache) |
| Postgres + PostGIS + pgvector | ~1 ГБ | ~4 ГБ |
| NestJS-бэкенд | ~0.5 ГБ | — |
| nginx + тайлы (pfo.pmtiles 957 МБ) | ~50 МБ | ~1 ГБ |
| OS + Docker + swap | ~0.3 ГБ + 4 ГБ swap | ~5 ГБ |
| PBF ПФО + SRTM-кэш | — | ~3 ГБ |
| **Итого** | ~3.5 ГБ (влезает) | ~18-22 ГБ |

> **Важно:** переход на ПФО (731 МБ PBF) увеличил graph-cache и RAM потребление
> GraphHopper по сравнению с исходной Кировской областью (~50 МБ PBF). Расширение
> до ПФО+СЗФО потребует VPS ≥ 8 ГБ.

Поток разработки: `download-osm.sh` → `docker compose up -d` → `dev:backend:log` /
`dev:frontend:log`. Первый старт GraphHopper импортирует граф + тянет SRTM (~1–3 мин),
затем грузится быстро.

Подробный гайд по деплою — [deployment.md](./deployment.md).

## 14. Записи архитектурных решений (ADR)

### ADR-001 — GraphHopper как движок роутинга
**Статус:** Принято. **Контекст:** нужен роутинг вел/пешком, высоты, генерация
round-trip, TSP, самохост, без внешних API. **Варианты:** GraphHopper, OSRM, Valhalla,
BRouter. **Решение:** GraphHopper — есть встроенные `round_trip` + `optimize` + высоты
SRTM; у OSRM нет высот и round_trip; Valhalla гибче, но нет чистой «случайной петли по
дистанции». **Следствия:** CH отключён (round_trip требует гибкого роутинга); LM для
скорости. BRouter можно добавить позже как «извилистый» велорежим.

### ADR-002 — Оставить Vue 3 + NestJS, не переходить на React/Next.js
**Статус:** Принято. **Решение:** оставить. Приложение — интерактивная карта-SPA; SSR
конфликтует с Leaflet/MapLibre (`window`/`document` везде); бэкенд остаётся NestJS. Переход
помогает, только если разработчик заметно свободнее в React.

### ADR-003 — pgvector на нашем Postgres, не платформа Supabase
**Статус:** Принято. **Решение:** расширение pgvector на одном Postgres (гео + семантика
в одной БД), оставить свой NestJS JWT (magic-link позже через лёгкую либу). Свой Supabase
нужен ~8 ГБ / ~10 контейнеров и не уживается с GraphHopper на 4 ГБ. **Следствия:** сами
доделываем auth-удобства, но остаёмся в бюджете.

### ADR-004 — Vercel AI SDK core для чат-компаньона, не Mastra
**Статус:** Принято. **Решение:** AI SDK core (`streamText`/`tool`/`stopWhen`) в браузере
с BYO-key. Mastra построен *поверх* AI SDK и добавляет агент-*бэкенд* (память/workflows/эвалы),
который мы намеренно не хостим — выносим интеллект наружу. **Следствия:** тонкая
Vue-composable-обёртка вместо `useChat`.

### ADR-005 — Векторные тайлы PMTiles, не растр
**Статус:** Реализовано ✅. **Решение:** карта работает на `pfo.pmtiles` (957 МБ, ПФО)
через Protomaps + MapLibre GL JS. Тайлы отдаются nginx-статикой. **Следствия:** ~1 ГБ
вместо 10–20 ГБ; подписи через тему Protomaps; без Mapbox; нет тайл-сервера.

### ADR-006 — N транспортных поверхностей над одним слоем capabilities
**Статус:** Принято (заменяя изначальные «три поверхности»). **Контекст:** REST (UI),
MCP (внешние агенты), чат (компаньон), **и Telegram-бот** всем нужна одна доменная логика.
**Решение:** пишем capabilities один раз, экспонируем через тонкие транспорты. TG-бот
использует **grammY** как NestJS-провайдер в том же процессе (~0 доп. RAM). **Следствия:**
добавление поверхностей дёшево; нет дублирования; Telegram — zero-install точка входа.

### ADR-007 — Медиа миссий хранится внешне, не на VPS приложения
**Статус:** Предложено. **Решение:** внешнее объектное хранилище (S3-совместимое: R2/B2/S3)
как основное; Nearventure хранит только метаданные + ссылки в Postgres. TG-бот может быть
релеем загрузки. **Следствия:** +1 внешняя зависимость для медиа; raw video не касается
диска VPS. Gaussian splatting потребляет из объектного хранилища на отдельном офлайн-GPU-пайплайне.

### ADR-008 — Nearventure — воронка сбора данных, а не хост сплаттинга/обработки
**Статус:** Принято. **Решение:** Nearventure только **собирает** (миссии + raw медиа +
метаданные + опц. контрибьют OSM/Commons). Вся тяжёлая обработка (gaussian splatting,
курация датасета) — downstream, офлайн-пайплайн на отдельном железе. **Следствия:** 4 ГБ
VPS остаётся реалистичным; чистое разделение сбора и обработки.

### ADR-009 — grammY для Telegram-бота, не Telegraf
**Статус:** Принято. **Решение:** grammY. Доказательства: стабильно активнее, нативные
TS-типы и полные доки; `nestjs-telegraf` тянет стагнирующий Telegraf, `@grammyjs/nestjs`
отстаёт до NestJS 9. **Следствия:** подключаем grammY вручную как NestJS-провайдер (без
обёртки-зависимости).
