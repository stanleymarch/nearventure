# Продукт: видение и сценарии

Компактное продуктовое введение для новых участников и AI-агентов. Техническая
карта — в [ARCHITECTURE.md](./ARCHITECTURE.md) и [AGENTS.md](../AGENTS.md).

## Видение

Nearventure — планировщик коротких приключений в выбранном регионе. Пользователь говорит, сколько у него времени, и получает готовый
маршрут: набор точек интереса, которые реально успеть пройти за бюджет времени,
с кольцевой логикой (вернуться к старту), GPX-экспортом и картой. Регион
настраивается: развёрнутая демо-версия работает на Приволжском федеральном
округе (ПФО), первая реализация покрывает Кировскую область.

Ключевые принципы:

- **Бюджет времени — главная валюта.** Сначала изохрона от стартовой точки,
  потом отбор POI, помещающихся в бюджет, потом порядок обхода и проверка
  замыкания кольца. Не «все точки», а «точки, которые успеваешь».
- **Данные — открытые, с provenance.** POI собираются из ЕГРКН/Минкульт,
  Wikimedia Commons, Wikidata, Wikivoyage и OSM; каждая точка несёт источник,
  лицензию и атрибуцию. Ничего не берётся «из интернета» без подтверждённой
  лицензии фото.
- **Несколько поверхностей, один capabilities-слой.** Веб (карта + каталог),
  Telegram-бот (геолокация → POI → маршрут → GPX) и Telegram Mini App (`/tg/`)
  зовут одни и те же NestJS-сервисы; доменная логика не дублируется.
- **Self-hosted по возможности.** PMTiles-подложка и GraphHopper (7 профилей)
  работают на своём стеке; внешние сервисы — только данные и картографические
  assets.

## Ключевые пользовательские сценарии

1. **«Что рядом + поехали» (бот).** Пользователь шлёт геопозицию в Telegram →
   бот присылает карточки ближайших POI с фото и атрибуцией → можно сразу
   построить маршрут или открыть Mini App.
2. **Планировщик по времени (веб).** Выбор стартовой точки, бюджета времени и
   транспорта → планировщик строит кольцевой маршрут из POI, которые
   помещаются в бюджет (изохрона + loop-quality + кластерное упорядочивание) →
   экспорт GPX.
3. **Каталог и деталь POI.** Поиск/фильтры по категории, веку, региону,
   источнику; карточка с фото (через защищённый медиа-прокси), атрибуцией,
   источниками и ссылками на оригинал.
4. **Копилка мини-аппа.** В Mini App POI добавляются в корзину → из неё строится
   маршрут по тем же правилам бюджета времени.

## Не-цели (сознательно не делаем)

- Криптовалюты, Stars/TON, in-app платежи (только внешние Boosty/CloudTips).
- «Весь интернет» как источник данных: только открытые реестры с лицензиями.
- Универсальный планировщик по всей стране: регион задаётся конфигурацией
  (территория + PBF + тайлы + POI-bundle); фокус для v1 — ПФО/Кировская область.

## Продуктовые решения и их причины (ADRs)

- **AGPL-3.0** — сетевая клаузула: кто запускает модифицированный сервис,
  обязан открыть изменения. Совместимо со стеком (всё MIT/Apache-2.0/BSD).
- **GraphHopper как ядро роутинга** — качество маршрутов важнее косметики;
  профили `car/bike/bike_touring/mtb/mtb_leisure/foot/foot_scenic`.
- **poi-toolkit как внешний producer** — Nearventure только импортирует
  manifest-валидируемый bundle; сам не собирает и не дёргает `psql`.
- **Медиа через прокси** — браузер не ходит по raw-ссылкам; backend сам
  скачивает (с SSRF-защитой), конвертирует в WebP и кеширует; неопубликованные
  внешние фото без лицензии не показываются.
